# `/git-help` — Git 规范与指令向导

## 0. 前置约束
> **⚠️ 必须执行**：在开始本工作流的任何操作前，AI 必须首先确认已查阅并加载了 **`git-standard`** 技能，并在后续操作中遵守其规定的所有限制条件。

## 1. 规范概述
向用户清晰介绍目标项目的 Git 核心规范（基于本地化后的 `git-standard` 技能内容提取）：
- **分支命名**：统一使用 `feature/xxx`、`bugfix/xxx`、`hotfix/xxx` 等前缀命名
- **远端协作**：feature 分支允许推送远端，用于多人协作、交接、CI 和审查，但必须短生命周期存在
- **验收门禁**：feature 合并前必须完成与风险匹配的验收，不能用“看起来能用”替代证据
- **提交规范**：建议使用 Conventional Commits，格式为 `<type>(<scope>): <subject>`；提交语言以目标团队规则为准
- **安全红线**：AI 未经用户明确授权不得执行提交操作；严禁将敏感凭证或大体积文件纳入版本控制
- **版本一致**：发布到 `main` 前建议遵守 `version-standard`，确保 Web / Server 版本与接口契约可追溯

## 2. 指令清单
向用户介绍当前可用的 Git 斜杠指令及其适用场景：
- **`/git-start`** — 开启新分支。仅在 `develop` 上可用，同步远端后按规范命名切出新的功能分支。
- **`/git-commit`** — 提交并推送。检查安全隐患、生成规范提交信息、获得授权后一键提交推送。
- **`/git-sync`**（别名 `/git-rebase`）— 变基同步。暂存未完成的代码，将当前分支 rebase 到最新 `develop`，遇冲突提供完整合并方案。
- **`/git-finish`** — 功能闭环。验收通过后 Squash 合并至 `develop` 并推送，清理本地和远端旧分支后引导开启新分支。
- **`/git-leave`**（别名 `/git-scratch`）— 临时存档。将当前进度提交推送至远端，切回 `develop`，不做合并。仅限派生分支使用。
- **`/git-abandon`** — 放弃分支。永久销毁当前分支所有进度，切回 `develop`。操作前强制发出不可逆警告。仅限派生分支使用。

## 3. 答疑
主动询问用户：「以上是当前 Git 协作规范与全部可用指令。如有任何疑问，请随时提出。」
