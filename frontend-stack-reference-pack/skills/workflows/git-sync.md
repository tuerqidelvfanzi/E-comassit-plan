# `/git-sync` — 变基同步

## 0. 前置约束
> **⚠️ 必须执行**：在开始本工作流的任何操作前，AI 必须首先确认已查阅并加载了 **`git-standard`** 技能，并在后续操作中遵守其规定的所有限制条件。

## 1. 保护工作区
- 执行 `git status` 检查是否存在未提交的改动。
- 若有未提交的内容，先执行暂存以确保工作区干净：
```bash
git stash
```

## 2. 拉取远端并变基
从远端获取最新主干状态，将当前分支变基到 `develop` 最新提交之上：
```bash
git fetch origin
git rebase origin/develop
```

## 3. 冲突处理
- 若 `rebase` 过程中出现冲突，**立即暂停后续操作**。
- AI 必须完整通读每一个冲突文件，扫描双方代码逻辑，然后向用户提交一份**详细的合并解决方案**：说明冲突原因，并逐文件建议是保留双方、取其一方、还是需要组合重构。
- 等待用户确认方案并完成代码修复后，执行：
```bash
git add .
git rebase --continue
```
- 重复此步骤直至 rebase 全部完成。

## 4. 恢复工作区
- 变基完成后，若第 1 步执行过 `git stash`，则恢复暂存内容：
```bash
git stash pop
```
- 向用户确认变基同步已完成，当前分支已基于最新的 `develop`。
