# `/git-commit` — 提交与推送

## 0. 前置约束
> **⚠️ 必须执行**：在开始本工作流的任何操作前，AI 必须首先确认已查阅并加载了 **`git-standard`** 技能，并在后续操作中遵守其规定的所有限制条件。

## 1. 安全预检
- 执行 `git status`，审查变更文件清单。
- 若发现敏感文件（`.env`、密钥文件等）或不应纳入版本控制的产物（`node_modules/`、`dist/`），立即向用户告警并要求处理。
- 执行 `git fetch origin`，比对本地分支与远端的同步状态。若本地落后于远端，向用户发出警告并建议先执行 `/git-sync`。

## 2. 变更摘要与提交信息
- 通过 `git diff --stat` 等方式总结本次改动范围。
- 按照 `git-standard` 规范生成**中文**提交信息，格式为 `<type>(<scope>): <subject>`。

## 3. 人类授权（强制卡点）
- 向用户完整展示：安全预检结果 + 变更文件列表 + 拟定的提交信息。
- **明确询问**：「请确认以上变动并授权本次提交。回复"确认"以继续。」
- **红线**：未获得用户明确授权前，严禁执行 `git commit`。

## 4. 提交与推送
获得授权后，依次执行：
```bash
git add .
git commit -m "<已授权的提交信息>"
git push origin <当前分支名>
```
执行完毕后，向用户确认提交与远端推送均已成功。
