## 调研概要

本次调研使用AnySearch技能进行深度搜索，覆盖以下方面：
- 认证方案对比 (Clerk vs Supabase Auth)
- 支付系统 (Stripe vs Paddle vs LemonSqueezy)
- AI Token计费追踪
- 多租户架构 (Supabase RLS)
- 国内支付方案

---

## 1. 用户管理系统深度调研

### 1.1 认证方案对比

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| Clerk | React组件完善, 社交登录强 | 需付费 | React项目 |
| Supabase Auth | 免费开源, RLS集成 | UI组件较弱 | 需要数据库集成 |
| NextAuth | 开源灵活 | 需自建UI | Next.js项目 |

推荐: Clerk + Supabase组合

### 1.2 Supabase RLS多租户

RLS在数据库层面强制隔离，性能优于应用层过滤。

### 1.3 团队协作功能

- 团队创建 (创建者自动成为Owner)
- 成员邀请 (邮箱邀请, 角色指定)
- 角色权限 (Owner/Admin/Member/Viewer)
- 使用配额 (按团队设置Token限额)

## 2. 费用消耗系统深度调研

### 2.1 Token计费追踪方案

开源参考项目:
- Tokdash (https://github.com/JingbiaoMei/tokdash) - Python实现
- Token Tracker (https://www.tokentracker.cc/) - 本地优先设计

技术实现: 在API边界拦截请求，记录input/output tokens和cost。

### 2.2 AI API计费模式

| 模式 | 说明 | 代表产品 |
|------|------|----------|
| 按Token | 按输入/输出Token计费 | OpenAI, Claude, MiniMax |
| 包月 | 固定月费, 不限量 | GitHub Copilot |
| 混合 | 订阅+按量 | Cursor, 本系统 |

本系统采用混合模式: 订阅决定基础配额, 超出部分按Token计费

### 2.3 Token消耗预估

| 操作 | 输入Tokens | 输出Tokens | 预估成本 |
|------|-----------|------------|----------|
| 标题优化 | 200 | 50 | 0.025元 |
| 描述改写 | 500 | 300 | 0.08元 |
| SKU生成 | 100 | 150 | 0.025元 |
| 竞品分析 | 1000 | 800 | 0.18元 |

## 4. 系统架构设计

### 4.1 整体架构

- Web Frontend: React 19 + Clerk + TanStack Query
- API Backend: Hono + Supabase + Token Tracker
- Auth: Clerk
- Database: Supabase PostgreSQL
- Payments: Paddle (海外) / 支付宝 (国内)
- AI: MiniMax (国内) + Claude/GPT (可选)

### 4.2 API设计

认证 (Clerk托管):
- POST /auth/signup
- POST /auth/signin

团队 (Supabase):
- GET/POST /api/teams
- GET/PATCH/DELETE /api/teams/:id

成员:
- GET /api/teams/:id/members
- POST /api/teams/:id/members/invite

消耗:
- GET /api/usage
- GET /api/usage/summary

充值:
- POST /api/recharge/paddle
- POST /api/recharge/alipay
