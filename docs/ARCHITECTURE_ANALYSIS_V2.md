## 2. 三层定义与边界

### 2.1 采集层（Collection）

**职责**：从源平台获取商品原始数据

**数据输入**：
- 源平台：淘宝/天猫、拼多多、1688、抖音、京东
- 采集方式：插件采集、链接直采、榜单批量采集

**数据输出**：
```json
{
  "rawProduct": {
    "source": "taobao",
    "sourceUrl": "...",
    "title": "原始标题",
    "price": 89,
    "images": [...],
    "skus": [...],
    "attributes": {...}
  }
}
```

**核心能力**：
| 能力 | 说明 |
|------|------|
| 分层抓取 | L1 JSON -> L2 JSON-LD -> L3 API -> L4 DOM |
| 反爬应对 | 随机延迟、UA轮换、代理池 |
| 数据清洗 | 标准化输出格式 |

### 2.2 处理层（Processing）

**职责**：对采集的数据进行优化、翻译、分析

**关键洞察**：用户提到的"在本平台的数据"实际上是指**选品洞察**能力

**数据输入**：
- 采集的原始商品
- 源平台竞品数据（用于同类分析）

**数据输出**：
```json
{
  "processedProduct": {
    "title": "优化后标题",
    "shortDescription": "短描述",
    "description": "详细描述",
    "skus": [...],
    "images": [...],
    "insights": {
      "competitorAnalysis": {...},
      "pricing": {...},
      "keywords": [...]
    }
  }
}
```

**核心能力**：
| 能力 | 说明 |
|------|------|
| AI优化 | 标题/描述翻译、本地化 |
| SKU生成 | 五段编码生成 |
| 价格计算 | 分市场倍率 |
| 违禁检测 | 品牌/国内标识/面料 |
| **竞品分析** | 在源平台找同类、类似产品（用户洞察需求） |

### 2.3 写入层（Publishing）

**职责**：将处理后的数据写入目标平台

**数据输入**：
- 处理后的商品数据
- 目标平台配置

**数据输出**：
- 目标平台草稿/商品

**核心能力**：
| 能力 | 说明 |
|------|------|
| 平台适配 | 越南Shopee、泰国TikTok等 |
| 表单填表 | DOM操作/API对接 |
| 状态跟踪 | pending/completed/failed |

## 3. 独立性分析

### 3.1 采集层独立性

**可以独立使用的场景**：
| 场景 | 说明 |
|------|------|
| 数据备份 | 仅采集存储，不处理 |
| 人工处理 | 采集后人工Excel整理 |
| 第三方对接 | 仅提供采集数据给其他系统 |

**依赖关系**：
- 输入：源平台（外部）
- 输出：原始商品数据

**结论**：✅ 完全独立

### 3.2 处理层独立性

**可以独立使用的场景**：
| 场景 | 说明 |
|------|------|
| 竞品分析 | 仅分析同类产品，不采集不上架 |
| 模板测试 | 不接真实数据，仅测试Prompt |
| 规则调整 | 不涉及采集和写入 |

**依赖关系**：
- 输入：商品数据（可来自采集或人工导入）
- 输出：优化后商品数据

**结论**：✅ 完全独立

### 3.3 写入层独立性

**可以独立使用的场景**：
| 场景 | 说明 |
|------|------|
| 手工上品 | 人工整理数据，直接填表 |
| 第三方数据 | 其他系统数据，本系统仅负责写入 |
| API对接 | 平台Open API直接写入 |

**依赖关系**：
- 输入：商品数据（可来自处理或人工）
- 输出：目标平台草稿

**结论**：✅ 完全独立

## 6. 架构优势

### 6.1 解耦优势

| 优势 | 说明 |
|------|------|
| 独立开发 | 三层可并行开发 |
| 独立测试 | 每层可单独测试 |
| 灵活组合 | 支持不同业务流程 |
| 易于扩展 | 新增平台只需扩展写入层 |
| 故障隔离 | 一层故障不影响其他层 |

### 6.2 业务优势

| 优势 | 说明 |
|------|------|
| 场景覆盖 | 满足采集、处理、写入的各种组合 |
| 竞品洞察 | 处理层支持竞品分析功能 |
| 批量分发 | 同一份数据可写入多个平台 |
| 模板复用 | 处理层的模板可复用于不同采集源 |

## 7. 潜在问题与对策

### 7.1 数据一致性问题

**问题**：采集、处理、写入三层数据可能不一致

**对策**：
- 使用唯一ID贯穿三层
- 数据校验在每层入口执行
- 状态机跟踪数据状态

### 7.2 性能问题

**问题**：大批量处理时性能瓶颈

**对策**：
- 采集：分布式采集
- 处理：队列+Worker
- 写入：并发填表+限流

### 7.3 平台差异问题

**问题**：不同目标平台规则差异

**对策**：
- 写入层抽象平台适配器
- 处理层输出标准化格式
- 适配器负责平台特定转换
