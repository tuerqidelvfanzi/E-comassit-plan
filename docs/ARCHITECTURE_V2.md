## 2. 独立性验证

### 2.1 各层独立性

| 层级 | 独立性 | 可单独使用场景 |
|------|--------|---------------|
| 采集层 | ✅ 完全独立 | 数据备份、人工处理、第三方对接 |
| 处理层 | ✅ 完全独立 | 竞品分析、模板测试、规则调整 |
| 写入层 | ✅ 完全独立 | 手工上品、API对接、第三方数据写入 |

### 2.2 依赖关系

```
采集层：
  输入：源平台（淘宝/拼多多/1688/抖音）
  输出：RawProduct

处理层：
  输入：RawProduct 或 竞品查询请求
  输出：ProcessedProduct + Insights

写入层：
  输入：ProcessedProduct
  输出：目标平台草稿
```

| 场景 | 用户需求 | 覆盖模块 |

| 场景A | 我看到淘宝一个爆款，想搬去Shopee | 采集→处理→写入 |

### 3.3 数据流向验证

```
路径1: 完整上品

路径2: 竞品分析
采集 → [raw] → 处理(竞品分析) → [insights] → 结束

路径3: 批量分发

路径5: 仅分析
输入竞品URL → 处理(竞品分析) → [insights] → 结束
```

## 4. 关键洞察：处理层的"本平台数据"

用户提到："数据处理（包含在本平台的数据，例如我在淘宝上想上新品，找同类，找类似产品）"

这个需求实际上是**竞品分析能力**，应该放在处理层：

```typescript
// 处理层内部能力
interface ProcessingModule {
  // 原有能力
  optimizeTitle(): void;
  generateSku(): void;
  calculatePrice(): void;
  checkBanned(): void;
  translate(): void;
  
  // 新增能力：竞品分析
  analyzeCompetitors(): CompetitorInsights;
  findSimilarProducts(): SimilarProduct[];
  getMarketTrends(): MarketTrends;
}
```

### 4.1 竞品分析能力

| 能力 | 说明 |
|------|------|
| 同类查找 | 在源平台找同类爆款 |
| 标题分析 | 分析TOP100标题关键词 |
| 定价参考 | 给出建议价格区间 |
| 趋势洞察 | 颜色/款式趋势分析 |

### 4.2 数据来源

```
竞品数据来源：
├─ 采集的历史数据（已有）
├─ 本次新采集的数据
└─ 平台公开数据（销量/评价）
```
