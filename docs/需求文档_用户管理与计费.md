## 1. 产品定位

为电商AI助手提供完整的SaaS运营能力:

- Token消耗追踪

## 2. 用户管理系统 (FR-UM)

### 2.1 功能架构

```
用户管理
├── 认证模块 (FR-UM-01)
│   ├── 邮箱注册/登录 (P0)
│   ├── 短信验证 (P0)
│   └── 密码重置 (P0)
├── 授权模块 (FR-UM-02)
│   └── RBAC角色 (P0)
└── 团队模块 (FR-UM-03)
    ├── 团队创建 (P1)
    ├── 成员邀请 (P1)
    └── 角色分配 (P1)
```

### 2.2 认证流程

```
注册:
  1. 输入邮箱 + 密码
  2. 发送验证码 (短信)
  3. 验证邮箱 + 手机
  4. 注册成功

登录:
  1. 输入邮箱 + 密码
  2. 可选: 发送验证码 (短信)
  3. 登录成功
```

### 2.3 角色权限

| 角色 | 说明 |
|------|------|
| Owner | 团队所有者，全部权限 |
| Admin | 管理员，管理成员/设置/充值 |
| Member | 成员，使用功能/查看消耗 |
| Viewer | 观察者，只读访问 |

## 3. 费用消耗系统 (FR-COST)

### 3.1 Token消耗

基于通义千问定价 (0.004元/1K输入, 0.012元/1K输出):

| 操作 | 输入Tokens | 输出Tokens | 成本 |
|------|-----------|------------|------|
| 标题优化 | 200 | 50 | 0.001元 |
| 描述改写 | 500 | 300 | 0.0056元 |
| SKU生成 | 100 | 150 | 0.0022元 |
| 竞品分析 | 1000 | 800 | 0.0136元 |
| 图片OCR | 500 | 200 | 0.0044元 |

### 3.2 预警规则

| 级别 | 阈值 | 通知 |
|------|------|------|
| 提醒 | 余额<50%配额 | 应用内 |
| 警告 | 余额<20%配额 | 应用内+邮件 |
| 紧急 | 余额<10%配额 | 应用内+短信 |
| 熔断 | 余额=0 | 暂停服务 |

## 5. 技术方案

### 5.1 技术栈

| 组件 | 方案 |
|------|------|
| 认证 | 自建邮箱注册 + 阿里云短信 |
| 数据库 | Supabase PostgreSQL + RLS |
| AI | MiniMax/通义千问 (OpenAI兼容) |
| 支付 | 银行聚合支付 |
| 短信 | 阿里云短信 |

### 5.2 数据模型

```typescript
// 用户
interface User {
  id: string;
  email: string;
  phone?: string;
  passwordHash: string;
  emailVerified: boolean;
  phoneVerified: boolean;
  createdAt: string;
}

// 团队
interface Team {
  id: string;
  name: string;
  ownerId: string;
  plan: 'free' | 'pro' | 'team' | 'enterprise';
  tokenQuota: number;
  tokenUsed: number;
  balance: number;  // 余额
}

// 消耗记录
interface UsageRecord {
  id: string;
  userId: string;
  teamId: string;
  action: string;
  model: string;
  inputTokens: number;
  outputTokens: number;
  cost: number;
  createdAt: string;
}

// 交易记录
interface Transaction {
  id: string;
  userId: string;
  teamId: string;
  type: 'recharge' | 'subscription' | 'consumption';
  amount: number;
  balanceBefore: number;
  balanceAfter: number;
  status: string;
  createdAt: string;
}
```

### 5.3 API设计

```
认证:
  POST /api/auth/register      # 注册
  POST /api/auth/login        # 登录
  POST /api/auth/send-code    # 发送验证码
  POST /api/auth/verify-code # 验证
  POST /api/auth/reset-password # 密码重置

团队:
  GET/POST   /api/teams
  GET/PATCH  /api/teams/:id
  GET        /api/teams/:id/members
  POST       /api/teams/:id/members/invite

消耗:
  GET /api/usage
  GET /api/usage/summary

支付:
  POST /api/pay/create       # 创建支付
  POST /api/webhook/pay     # 支付回调

订阅:
  GET  /api/subscription
  POST /api/subscription/change
```
