### 1.1 调研发现

#### 竞品方案

| 方案 | 代表产品 | 特点 |
|------|----------|------|
| Clerk | Modern auth | React友好, 托管UI组件 |

## 4. 系统架构

### 4.1 数据模型

```
User (Clerk)
├── id: string
├── email: string
├── name: string
└── metadata: {...}

Team (Supabase)
├── id: uuid
├── name: string
├── owner_id: FK(User)
├── plan: enum(free/pro/team/enterprise)
├── token_quota: int
└── token_used: int

TeamMember
├── team_id: FK(Team)
├── user_id: FK(User)
└── role: enum(owner/admin/member/viewer)

UsageRecord
├── id: uuid
├── user_id: FK(User)
├── team_id: FK(Team)
├── action: enum(title_optimize/desc_rewrite/...)
├── input_tokens: int
├── output_tokens: int
├── cost: decimal
└── created_at: timestamp

Transaction
├── id: uuid
├── user_id: FK(User)
├── type: enum(recharge/subscription/refund)
├── amount: decimal
├── balance_before: decimal
├── balance_after: decimal
└── created_at: timestamp

Subscription
├── id: uuid
├── user_id: FK(User)
├── team_id: FK(Team)
├── plan: enum(free/pro/team/enterprise)
├── status: enum(active/cancelled/expired)
├── started_at: timestamp
├── expires_at: timestamp
└── auto_renew: boolean
```

### 4.2 API设计

```
# 认证 (Clerk托管)
POST /auth/signup
POST /auth/signin
POST /auth/signout

# 团队管理
GET    /teams
POST   /teams
GET    /teams/:id
PATCH  /teams/:id
DELETE /teams/:id

# 成员管理
GET    /teams/:id/members
POST   /teams/:id/members/invite
PATCH  /teams/:id/members/:userId
DELETE /teams/:id/members/:userId

# 消耗记录
GET  /usage?period=day&teamId=xxx
GET  /usage/summary
GET  /usage/ranking

# 账户余额
GET  /account/balance
GET  /account/transactions

# 订阅管理
GET  /subscription
POST /subscription/change
POST /subscription/cancel

# 充值
POST /recharge/alipay
POST /recharge/wechat
```

## 6. 决策点

### Q1: 认证方案选择
- Clerk (托管UI) vs Supabase Auth (自建)
- **建议**: Clerk - 开发效率高, UI组件完善

### Q2: 存储方案
- Supabase vs 自建PostgreSQL
- **建议**: Supabase - RLS权限控制强, 实时订阅

### Q3: 支付接口
- 支付宝当面付 vs Stripe
- **建议**: 支付宝 - 目标用户在国内

### Q4: 计费精度
- 按token vs 按次
- **建议**: 按token - 更公平, 与API成本挂钩
