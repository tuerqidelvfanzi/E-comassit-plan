## 1. 调研问题

## 2. 主流 ERP / 铺货工具（行业对照）

| 工具类型 | 代表 | 卖家怎么用 | 与「小工具」的关系 |
|----------|------|------------|-------------------|
| 全链路 ERP | 店小秘、妙手 ERP、客优云、EasyBoss | 采集 100+ 货源 → 采集箱 → 认领规则 → 多站点多店铺一键发品 | **我们要替代的是其中「上品编辑」这一段**，不是订单/仓储/财务 |
| 能力共性 | 同上 | 插件/链接/关键词/整店采集；定价模板；图片翻译/去重；违禁词检测；批量刊登 | 清晰规则用**模板+规则引擎**；「智能标题」多为营销表述，需拆成可验证子任务 |
| 痛点（行业文） | 店小秘博客等 | 新手：不熟悉规则即违规；铺货：SKU 量大、合规排查耗时；店群：多店同步与重复检测 | 对应我方：**高频+重复+需判断** 三类需求（见 PRD §2） |

来源示例：[店小秘 TikTok 上品 ERP 功能](https://www.dianxiaomi.com/blog/article/507)、[Shopee 一键多站发布](https://www.dianxiaomi.com/blog/article/15)、[妙手 Shopee 采集发布](https://erp.91miaoshou.com/shopee.html)、[DNY123 铺货软件讨论](https://www.dny123.com/t/i0zdbnaf)

**观点摘要**

- 卖家要的不是「又一个 ERP」，而是**把最耗时的编辑环节压到分钟级**。  
- 行业工具已覆盖采集与批量发品；差异化在**类目级模板 + 合规 + 本地化质量**。  
- 多店矩阵依赖**认领规则**（一次配置、长期生效）— 我方可用「类目模板 + 目标市场配置」类比，但 v2.0 先做**单店单市场闭环**。

## 3. 平台规则 vs 实操习惯（重要冲突）

### 3.1 越南 Shopee 标题

| 来源 | 说法 |
|------|------|
| **原始实操**（`BUSINESS_REQUIREMENTS_DEV.md`） | 越南语标题 **≤20 字符**，汉字压到 9–10 字内，超了用外部翻译工具 |
| **Shopee 卖家学院（VN）** | 越南语有音标；名称需与图片一致；避免 spam/夸大 |
| **东南亚 SEO 培训文** | 常见建议 **60–120 字符** 利于搜索；关键词放前、属性词优先 |

来源：[Shopee VN 卖家学院](https://banhang.shopee.vn/edu/article/2100)、[TukiGroup SEO](https://tukigroup.vn/tieu-de-san-pham-chuan-seo-hanh-vi-tim-kiem-shopee/)、[Shopee PH Listing 质量基线](https://seller.shopee.ph/edu/article/27394)

**结论（写入 PRD 待确认项）**

- 「20 字」更可能来自**跨境运营内部工作流/简易描述字段**，与 Shopee 当前 SEO 最佳实践**不一致**。  
- v2.0 需求应区分：**短标题/短描述（20 字）** vs **搜索标题（60–120 字）** — 需运营一次确认字段映射。

### 3.2 图片与 Listing 质量

- Shopee 强调：标题≥10 字、描述≥60 字或配图、无 spam、图文一致（PH 教育中心基线）。  
- 实操文档强调：9 张 1:1、消除质保/包邮/LOGO、中→越翻译 — **规则清晰，适合流水线，不适合端到端 LLM 胡写**。

### 3.3 TikTok Shop 泰国

- 原始资料：主图 ≥5、参考同行标题、五段 SKU、×2.5 价、无品牌。  
- 技术侧：TikTok Shop 抓取需 Playwright + 代理，SEA 多区（th/vn/ph/id）API/页面结构差异大（Apify/Syphoon 等文档 2025–2026）。

## 4. GitHub / 技术社区

| 方向 | 代表 | 启示 |
|------|------|------|
| 多平台爬虫 | [ortizdavidg/shopee-lazada-tiktok-scraper-crawler](https://github.com/ortizdavidg/shopee-lazada-tiktok-scraper-crawler) | Playwright + 代理 + 分层字段 — 对应我方 **Worker 直采/竞品** |
| 东南亚分析 | [nerufuyo/neru-scrapper](https://github.com/nerufuyo/neru-scrapper) | 关键词搜索 → 价格/评分导出 — 对应 **选品洞察** |
| SaaS 抓取 | Apify TikTok Shop Scraper、FalconScrape 指南 | 产品 URL/店铺 ID 批量、区域码 — **竞品分析数据源** |

**程序员社区共识**

- 反爬与 DOM 变更是常态 → **插件填表 + selector 映射表** 必须可热更新。  
- 采集与刊登分离 → 与「采集-处理-写入」三层一致。  
- 批量铺货工具多，**质量在编辑环节**，不在「能不能传上去」。

## 5. AI 在 Listing 中的**真实**价值（学术与产业）

| 研究/观点 | 结论 |
|-----------|------|
| [Amazon Science RAG 标题翻译](https://arxiv.org/html/2409.12880) | 商品标题短、缺语境 → **RAG + 同类 bilingual 样例** 比裸翻好（chrF +15%） |
| [ACL 2024 跨语标题生成](https://aclanthology.org/2024.ecnlp-1.6.pdf) | 不要只翻译，要 **summarize + 长度约束**（按市场字数） |
| [Cross-border AI tools 2026](https://ecomaiskills.com/blog/cross-border-ecommerce-ai-tools-2026) | 2026 有效做法：**分析头部卖家再写**，而非 ChatGPT 万能文案 |

**归纳：AI 应做的 = 「模糊规则 / 需判断」**

- 在字数极限下保留哪些词（语义压缩）  
- 参考竞品标题风格（泰 TikTok）  
- 图片上哪些字必须消、哪些保留（结合 OCR + 类目策略）  
- 面料/功效表述是否与属性一致（风险判断）  
- 同品类历史爆款关键词归纳（选品辅助）

**AI 不应主导 = 「清晰规则」**

- 价格 ×3.5 / ×2.5、库存 50、SKU 五段格式、白色钩子参数  
- 图片数量、尺寸 800×800、包裹 10-5-10  
- 违禁品牌词表、国内标识删除清单

## 6. 品类 SKU 模式（调研 + 原始资料综合）

| 模式 | 典型品类 | SKU 规模 | 模板应固定什么 |
|------|----------|----------|----------------|
| **A 矩阵** | 儿童服装、T恤 | 15–60（色×码×正反面） | 颜色表、码表、序号、钩子、**系统 Prompt：压缩标题+翻译** |
| **B 组合** | 吊灯、小家电 | 3–27（功率×色温×控制） | 维度笛卡尔积、规格表 HTML、安装说明槽位 |
| **C 定制** | 橱柜、商用设备 | 1–5 + 定制项 | 宽深高 range、加价项、询价话术 — **AI 辅助生成定制说明，不自动生成 60 个 SKU** |

**选品研究（同品类）应产出**

- TOP 标题词、价格带、主色/主码、爆款主图结构  
- 写入 **CompetitorInsights** → 作为 RAG 样例进入处理 Prompt（与 Amazon 论文路径一致）

## 7. 调研结论 → 产品策略

1. **定位**：轻量 **AI 辅助上品助手**，替代 ERP 里「采集箱→人工编辑→发布」段，不碰订单仓储。  
2. **架构**：清晰规则 = 规则引擎 + 类目模板；模糊判断 = LLM + RAG（竞品/历史爆款）。  
3. **流程**：从「ERP 内 13 步点击」改为「采集箱 → 工作台（管线+人工确认）→ 插件/API 写入」。  
4. **风险**：越南 20 字规则需与平台 SEO 要求 **ADR 定稿**；六段 SKU（+B/+H）以原始谷歌报告为准待确认。
